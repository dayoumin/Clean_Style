일터 존중·안전 자료 사용 및 문항 관리 기준

공식 자료를 직접 복제하지 않고 기준으로 활용하기 위한 사용 정책, 문항 출처 관리, 검토 절차

목차

1. 고정 결정

  • 앱은 공식 자가검진 도구, 공식 체크리스트, 연구척도를 그대로 탑재하지 않는다.
  • 공식 자료는 판단 기준, 유형 분류, 처리 절차, 도움 연결 경로를 정리하는 근거로 사용한다.
  • 앱 문항은 공식 기준을 바탕으로 자체 설계하고, 내부 매핑표에서 어떤 기준을 근거로 만들었는지 추적한다.
  • 공식 문구를 사용자 화면에 길게 인용하지 않는다. 필요한 경우 짧은 출처 링크와 문서명을 제공한다.
  • 사용자 화면이 import하는 문항 데이터에는 내부 출처·검토 메타데이터를 포함하지 않는다. 출처 관리는 별도 내부 파일과 문서에서 유지한다.
  • 정신건강은 진단·점수화가 아니라 도움 연결이 필요한 신호를 확인하는 안전 장치로만 둔다.
  • 사용자에게 이름, 소속기관, 부서, 직위, 연락처를 묻지 않는다.

2. 자료별 사용 정책

자료 역할 허용 방식 금지·보류 방식 결정
공공분야 갑질 근절 가이드라인 공공기관 맥락의 갑질 유형, 판단 기준, 피해자 보호, 발생 위험진단 참고 유형과 절차를 요약해 내부 기준으로 사용. 문항은 자체 작성. 사용자 화면에는 문서명과 링크만 제공 가능. 위험진단 체크리스트를 그대로 복사하거나 일부 표현만 바꿔 앱 문항으로 탑재하는 방식은 이용조건 확인 전 보류. 기준 참고직접 사용 보류
직장 내 괴롭힘 판단 및 예방·대응 매뉴얼 지위·관계의 우위, 업무상 적정범위 초과, 신체적·정신적 고통 또는 근무환경 악화 여부 판단 판단 축을 앱 로직과 결과 설명의 근거로 사용. 공식 기준을 쉬운 질문으로 재구성. 사례, 문항, 체크리스트, 매뉴얼 본문을 긴 문장 그대로 앱에 재게시하는 방식은 보류. 판단 기준 사용자체 문항화
국가정신건강정보포털 콘텐츠 이용안내 마음건강 자가검진의 공식 출처와 콘텐츠 이용조건 확인 자가검진 도구는 앱에 넣지 않고 공식 페이지로 링크아웃. 앱 내부에는 별도 설계한 도움 필요 신호만 사용. 자가검진 문항, 결과 해석, 점수 체계를 앱에 직접 탑재하거나 변형해 사용하는 방식은 금지. 직접 탑재 금지링크아웃
109 자살예방상담전화, 112, 119, 정신건강복지센터 긴급 위험과 비긴급 상담 연결 전화번호, 기관명, 공식 링크처럼 사실 정보는 사용자 안내에 사용. 위기 표현이 있으면 일반 조언보다 먼저 표시. AI가 위기 수준을 확정 판정하거나, 전문기관 연결 대신 자체 상담으로 대체하는 방식은 금지. 도움 연결
NAQ-R, COPSOQ, PHQ-9, GAD-7 등 연구·선별 도구 문항 설계 방식, 빈도 질문 방식, 위험영역 분류 참고 도구의 구조적 아이디어만 참고. 사용 허가와 번역판 조건이 확인된 경우에만 직접 사용 검토. 문항을 그대로 번역하거나 일부만 바꿔 사용하는 방식은 금지. 연구 참고직접 사용 금지
“공식 자료 기반”은 공식 문항을 복사한다는 뜻이 아니다. 이 프로젝트에서는 공식 기준을 근거로 자체 문항을 만들고, 원문·문항·체크리스트를 직접 쓰려면 별도 이용조건 확인 또는 허가가 필요하다.

3. 문항화 규칙

규칙 적용 방식 예시
기준 기반 자체 문항 공식 기준을 사용자 언어로 바꾸되 원문 표현을 그대로 복사하지 않는다. “상대가 거절하기 어려운 위치에 있었나요?”
판정 단정 금지 “갑질입니다”, “우울증입니다”처럼 단정하지 않고 가능성, 기록, 상담, 도움 연결로 표현한다. “직장 내 괴롭힘 판단 요소에 가까울 수 있습니다.”
두 입구 분리 내 행동 점검은 예방 행동, 내가 겪은 일 점검은 보호와 도움 연결 중심으로 결과를 낸다. “표현을 바꿔 다시 지시하세요” / “기록 후 상담창구에 문의하세요”
개인정보 최소화 이름, 기관명, 부서, 실명, 연락처를 묻지 않는다. 자유입력에는 식별정보를 쓰지 말라고 안내한다. “실명이나 기관명은 쓰지 말고 상황만 적어주세요.”
마음건강 별도 안전장치 갑질 점수와 섞지 않고 도움 연결 필요 여부만 확인한다. “지금 혼자 있기에 위험하다고 느끼면 109, 112, 119에 바로 연락하세요.”
근거 추적 필수 문항마다 공식 근거, 이용조건, 자체 문항 여부, 검토상태를 기록한다. derived_or_direct = 기준 기반 자체 문항

4. 문항 관리 필드

필드 필수 설명
question_id필수문항 고유 ID. 예: respect_action_001
version필수문항 버전. 문구·점수·근거 변경 시 증가.
entry필수내 행동 점검, 내가 겪은 일 점검, 공통
domain필수갑질 유형, 괴롭힘 판단, 마음위기 신호, 도움 연결 등
question_text필수사용자에게 보이는 자체 작성 문항
answer_options필수예/아니오, 빈도, 강도, 해당 없음 등 응답 체계
source_title필수근거 문서명
source_url필수공식 게시 페이지 또는 PDF URL
published_date필수근거 문서 발행일 또는 게시일
retrieved_at필수자료 확인일
section_or_page필수근거가 되는 장, 절, 페이지, 표 이름
basis필수문항이 반영한 판단 기준
source_text_summary필수원문 복사가 아닌 내부 요지
use_condition필수기준 참고, 링크아웃, 직접 사용 금지, 허가 필요 등
derived_or_direct필수기준 기반 자체 문항, 직접 인용, 링크아웃 중 하나
risk_flags필수법률오인, 의료오인, 개인정보, 위기표현 등 위험 표시
result_mapping필수응답이 어떤 결과 등급과 안내문에 연결되는지
expert_reviewer운영 전 필수노무, 인권, 정신건강 등 검토자
review_date운영 전 필수마지막 검토일
review_status필수초안, 내부검토, 전문가검토, 운영중, 폐기

5. 문항 생애주기

상태 조건 다음 단계
초안 공식 기준을 바탕으로 자체 문항을 작성한 상태 근거 문서와 이용조건 입력
출처매핑 완료 source_url, section_or_page, basis, use_condition이 채워진 상태 내부 리뷰
내부검토 문항이 단정적이지 않고 개인정보를 묻지 않으며 두 입구 중 하나에 맞는지 확인 전문가 검토 또는 폐기
전문가검토 법·노무, 인권, 정신건강 영역별로 표현과 도움 연결 기준을 확인 시범 운영
시범 운영 사용자 혼동, 과잉 판정, 도움 연결 누락, 모바일 UI 문제를 확인 운영중 또는 수정
운영중 문항, 결과, 프롬프트, 도움 안내가 검토 완료된 상태 자료 개정 시 재검토
폐기 근거가 약하거나 오인 위험이 크거나 공식 자료 개정으로 부적합해진 상태 결과 로직에서 제거

6. 문항 매핑 예시

근거 기준 앱 문항 예시 주의점
지위 또는 관계의 우위 상대가 내 요청을 거절하기 어려운 위치에 있었나요? 상급자만 전제하지 않고 선임자, 담당자, 민원 관계 등 관계상 우위를 포함한다.
업무상 적정범위 초과 그 요구가 담당 업무나 공식 역할과 직접 관련이 있었나요? 업무상 필요성과 방식의 적정성을 나눠 후속 문항에서 확인한다.
신체적·정신적 고통 또는 근무환경 악화 그 일 이후 출근, 업무 수행, 수면, 불안에 영향이 있었나요? 정신건강 진단으로 해석되지 않도록 도움 연결 기준으로만 사용한다.
사적 지시 또는 사적 이익 요구 업무와 무관한 개인적 부탁이나 심부름이 포함되어 있었나요? 공공분야 갑질 유형을 참고하되 체크리스트 문구를 그대로 쓰지 않는다.
긴급 위기 신호 지금 혼자 있기에 위험하다고 느끼거나 스스로를 해칠 생각이 있나요? 점수화하지 않고 즉시 109, 112, 119 또는 가까운 사람에게 연결하도록 안내한다.

7. 구현 전 게이트

  • 자료 게이트 각 공식 문서의 이용조건, 직접 사용 여부, 링크아웃 여부가 문서화되어야 한다.
  • 문항 게이트 모든 문항은 필수 관리 필드가 채워져야 하고, derived_or_direct가 “기준 기반 자체 문항”이어야 한다.
  • 표현 게이트 갑질·괴롭힘·정신건강을 단정하지 않고 가능성, 기록, 상담, 도움 연결 중심으로 표현해야 한다.
  • 개인정보 게이트 이름, 소속, 연락처를 묻지 않고 자유입력 원문 저장을 기본값으로 하지 않아야 한다.
  • 파일럿 게이트 검토 상태가 초안이면 운영 배포에서 공개하지 않고 내부 검토용으로만 접근해야 한다.
  • 위기 게이트 자해·자살·폭력·즉각적 안전위험 표현은 일반 결과보다 도움 연결을 우선해야 한다.
