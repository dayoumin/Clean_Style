Product & Diagnostic Architecture

하나의 코드, 세 제품, 세 개의 독립 진단

세 제품은 공통 화면 기반을 공유하지만 문항·채점·결과 해석은 진단별로 분리합니다. 배포 주소를 나누는 것만으로 진단이 분리되지는 않으므로 제품 설정과 진단 모듈을 함께 분리해야 합니다.

학생 제품은 자동 배포가 중지되었고, 성인 15문항·3축 채점·8개 결과·결과 저장 경로가 차단되었습니다. 학생 문항과 피드백 체계가 검토되기 전까지 /test와 /result에는 준비 상태만 표시합니다.
1 · 세 제품

사용자에게 보이는 앱은 이렇게 구분한다

제품대상과 목적포함 진단AI
clean-style 성인의 청렴 업무스타일 자기발견 성인 청렴 3축 진단: 원칙-유연, 투명-신중, 독립-협력과 8개 스타일 사용
clean-style-plus 성인의 청렴과 일터 존중을 함께 점검 성인 청렴 진단 + 내 행동 점검 + 내가 겪은 일터 존중 점검 사용
clean-style-student 한국 중·고등학생의 상황 선택·판단 이유 탐구와 수업 활동 학생 청렴 의사결정 진단. Rest 과정·한국 교육 가치·잠정 관찰영역·피드백 스타일 사용하지 않음

clean-style-plus는 성인 청렴 진단에 별도 존중 진단을 추가한 제품이고, clean-style-student는 성인 진단을 꾸민 화면이 아니라 문항과 채점이 다른 별도 진단입니다.

2 · 현재 구조

지금 코드에서 공유되는 것

영역현재문제
제품 선택src/products에서 제품별 대상·진단·AI·존중 기능·기록 사용 여부를 정의공통 화면 전체가 아직 진단 계약을 사용하지는 않음
성인 청렴src/diagnostics/adult-integrity 호환 어댑터로 기존 15문항·3축·8스타일을 제공원본 데이터는 아직 src/data/questions.ts에 있음
일터 존중별도 진단 정의와 제품 등록을 갖고 clean-style-plus에서만 활성화공통 진단 실행 화면으로의 통합은 후속 작업
학생용학생 진단 정의는 unscored-p0 상태이며 성인 화면·API·기록을 차단검토된 학생 문항과 피드백 구현이 아직 필요
저장성인 3축 필드와 배열 위치 기반 답변을 D1·URL·로컬 히스토리에 저장진단 종류·문항 버전·채점 버전을 구분할 수 없음
배포기본·Plus는 main 푸시, 학생은 수동 실행학생은 승인 전 배포하지 않으며 기본·Plus는 푸시 전 배포 영향을 확인해야 함
3 · 목표 구조

공통 제품 기반과 진단 모듈을 분리한다

src/
  diagnostics/
    core/                    공통 질문·응답·세션·결과 계약
    adult-integrity/         성인 15문항·3축·8스타일
    workplace-respect/       행동·경험 진입, 위험축·도움 경로
    student-integrity/       학생 상황·이유·피드백·보호 정책
  products/
    default.ts               clean-style 제품 조합
    plus.ts                  clean-style-plus 제품 조합
    student.ts               clean-style-student 제품 조합
  components/assessment/     공통 진행·선택·중단·접근성 UI
공통으로 공유진단별로 분리
세션 시작·중단, 진행률, 접근성, 반응형 레이아웃, 오류 처리, 버전 필드, 이벤트 계약 대상, 목적, 문항, 응답 방식, 채점, 결과 문구, 저장 정책, 안전·위기 대응, 검증 근거
브랜치를 제품별 장기 저장소처럼 유지하지 않습니다. main에서 공통 코드와 세 제품 정의를 함께 관리하고, 빌드할 때 제품 설정을 선택합니다. 제품별 실험은 짧은 기능 브랜치에서 작업한 뒤 검토 후 main으로 합칩니다.
4 · 공통 계약

먼저 코드가 진단을 구분할 수 있어야 한다

필드예시필요 이유
productIdclean-style-student어느 제품에서 실행됐는지 구분
instrumentIdstudent-integrity성인 청렴·존중·학생 청렴을 분리
instrumentVersionstudent-p0문항 변경 전후의 응답 혼합 방지
scoringVersionunscored-p0검증 전 무채점과 검증 후 채점을 구분

choiceId·reasonIdask-adult·safety행동 선택과 판단 이유를 분리해 저장

학생용은 초기에는 서버 저장을 사용하지 않습니다. 위 계약은 내부 프로토타입과 테스트에서도 사용해 나중에 연구 파일럿으로 전환할 때 성인용 데이터 구조를 재사용하지 않게 합니다.

5 · 학생용 단계별 계획

화면보다 진단 경계를 먼저 만든다

단계작업완료 기준
0. 배포 잠금 학생 워크플로를 수동 실행으로 전환하고 공개 학생 주소에는 준비 중 화면만 유지 학생 코드 작업이 main에 들어가도 자동 배포되지 않음
1. 공통 기반 분리 제품 정의와 진단 계약 생성, 기존 성인 청렴을 adult-integrity 모듈로 감쌈 기존 clean-style 결과가 바뀌지 않고 기존 테스트 통과
2. 학생 무채점 프로토타입 학생 전용 경로·문항형·행동 선택+이유 선택 UI, 이름·공유·AI·서버 저장 제거 성인 질문·3축·8스타일 코드가 학생 화면에서 사용되지 않음
3. 콘텐츠 공동설계 30~48개 후보 상황, 전문가 평정, 중·고등학생 인지면담과 수정 이력 학교급별 표현·선택지·안전성 기준을 통과한 후보 문항풀 확보
4. 피드백 규칙 과정별 관점 카드, 혼합 관점·아직 분류하지 않음, 성장 질문과 미션 구현 검증 전 대표 스타일·백분위·실제 행동능력 표현이 없음
5. 연구 파일럿 승인된 동의·최소 수집·버전 계약, 인지면담 후 예비조사와 구조·공정성·안정성 분석 사전 등록한 검증 기준과 학생 보호 운영기준 충족
6. 제한 출시 검증 결과에 따라 6개 영역·4스타일을 수정·통합·폐기하고 교사용 수업안과 함께 배포 근거 문서, 오용 금지, 삭제·위기응답, 롤백과 스모크 테스트 완료

7 · 작업 묶음

실제 개발 순서

  1. 완료 · 배포 제어: 학생 자동 배포를 중지하고 수동 실행만 허용.
  2. 완료 · 구조 분리 기반: 제품 설정, 진단 등록부, 성인 청렴 호환 어댑터와 제품 구성 회귀 테스트.
  3. PR 3 · 학생 골격: 학생 전용 모듈·경로·무채점 샘플 문항·결과 경계와 저장 차단.
  4. PR 3 선행 계약: 배열 위치 대신 productId, instrumentId, questionId, choiceId, reasonId를 사용하는 버전형 응답 계약 정의.
  5. 콘텐츠 작업: 코드와 분리된 문항 등록부에서 후보 상황·전문가 평정·인지면담을 진행.
  6. PR 4 · 검토된 콘텐츠: 승인된 문항 버전과 이유 선택지, 접근성·모바일 UI 반영.
  7. PR 5 · 피드백: 검증 수준에 맞는 관점 요약·혼합·무분류 결과와 성장 미션.
  8. 파일럿 이후: 승인된 경우에만 연구 저장·집계 기능을 별도 기능 플래그로 추가.
다음 작업은 학생 전용 골격과 문항 등록부입니다. 배포 잠금과 제품·진단 경계는 마련되었으므로, 검증 전에는 점수나 유형을 만들지 않는 원칙을 유지하면서 학생용 상황 문항과 피드백 화면을 구현합니다.
