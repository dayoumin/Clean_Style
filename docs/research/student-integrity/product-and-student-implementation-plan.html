Product & Diagnostic Architecture

하나의 코드, 세 제품, 세 개의 독립 진단

세 제품은 공통 화면 기반을 공유하지만 문항·채점·결과 해석은 진단별로 분리합니다. 배포 주소를 나누는 것만으로 진단이 분리되지는 않으므로 제품 설정과 진단 모듈을 함께 분리해야 합니다.

학생 제품은 자동 배포가 중지되었고, 성인 15문항·3축 채점·8개 결과·결과 저장 경로가 차단되었습니다. 현재 /test는 검증 전 예시 3개로 행동 선택·이유 선택·건너뛰기 흐름을 점검합니다. 다음 결과 화면은 공모전용 교육 데모로서 공통 탐색가와 4개 관점 동료, 숫자 없는 6축 관점 지도를 제공하되, 연구용 점수·대표 유형·능력 판정·서버 저장과 분리합니다.
1 · 세 제품

사용자에게 보이는 앱은 이렇게 구분한다

제품대상과 목적포함 진단AI
clean-style 성인의 청렴 업무스타일 자기발견 성인 청렴 3축 진단: 원칙-유연, 투명-신중, 독립-협력과 8개 스타일 사용
clean-style-plus 성인의 청렴과 일터 존중을 함께 점검 성인 청렴 진단 + 내 행동 점검 + 내가 겪은 일터 존중 점검 사용
clean-style-student 한국 중·고등학생의 상황 선택·판단 이유 탐구와 수업 활동 학생 청렴 의사결정 진단. Rest 과정·한국 교육 가치·잠정 관찰영역·피드백 스타일 사용하지 않음

clean-style-plus는 성인 청렴 진단에 별도 존중 진단을 추가한 제품이고, clean-style-student는 성인 진단을 꾸민 화면이 아니라 문항과 채점이 다른 별도 진단입니다.

2 · 현재 구조

지금 코드에서 공유되는 것

영역현재문제
제품 선택src/products에서 제품별 대상·진단·AI·존중 기능·기록 사용 여부를 정의공통 화면 전체가 아직 진단 계약을 사용하지는 않음
성인 청렴src/diagnostics/adult-integrity 호환 어댑터로 기존 15문항·3축·8스타일을 제공원본 데이터는 아직 src/data/questions.ts에 있음
일터 존중별도 진단 정의와 제품 등록을 갖고 clean-style-plus에서만 활성화공통 진단 실행 화면으로의 통합은 후속 작업
학생용학생 진단 정의는 unscored-p0 상태이며 성인 화면·API·기록을 차단검토된 학생 문항과 피드백 구현이 아직 필요
저장성인 3축 필드와 배열 위치 기반 답변을 D1·URL·로컬 히스토리에 저장진단 종류·문항 버전·채점 버전을 구분할 수 없음
배포기본·Plus는 main 푸시, 학생은 수동 실행학생은 승인 전 배포하지 않으며 기본·Plus는 푸시 전 배포 영향을 확인해야 함

세션 시작·중단, 진행률, 접근성, 반응형 레이아웃, 오류 처리, 버전 필드, 이벤트 계약 대상, 목적, 문항, 응답 방식, 채점, 결과 문구, 저장 정책, 안전·위기 대응, 검증 근거

5 · 학생용 단계별 계획

화면보다 진단 경계를 먼저 만든다

단계작업완료 기준
0. 배포 잠금 학생 워크플로를 수동 실행으로 전환하고 공개 학생 주소에는 준비 중 화면만 유지 학생 코드 작업이 main에 들어가도 자동 배포되지 않음
1. 공통 기반 분리 제품 정의와 진단 계약 생성, 기존 성인 청렴을 adult-integrity 모듈로 감쌈 기존 clean-style 결과가 바뀌지 않고 기존 테스트 통과
2. 초기 무채점 프로토타입 학생 전용 경로·문항형·행동 선택+이유 선택·건너뛰기 UI, 이름·공유·AI·서버 저장 제거 완료: 검증 전 예시 3개와 무채점 선택 돌아보기 화면, 결과 전달 후 삭제와 이동 실패 시 5초 내 삭제 적용
3. 콘텐츠 공동설계 30~48개 후보 상황, 전문가 평정, 중·고등학생 인지면담과 수정 이력 진행 중: 6개 영역 12개 2차 초안, 측정 목표·가치 갈등·수정 이력과 검토 절차를 구성했으며 전문가·학생 검토가 남음
4. 피드백 규칙 공모전 데모 규칙과 연구 후보 규칙을 분리하고, 행동×이유 패턴·관점 동료·숫자 없는 6축 지도·성장 질문을 구현 대표 유형을 자동 판정하지 않고 모든 학생을 관점 탐색가로 표현하며 연구용 산출 규칙과 별도 모듈로 관리
5. 연구 파일럿 승인된 동의·최소 수집·버전 계약, 인지면담 후 예비조사와 구조·공정성·안정성 분석 사전 등록한 검증 기준과 학생 보호 운영기준 충족
6. 제한 출시 검증 결과에 따라 6개 영역·4스타일을 수정·통합·폐기하고 교사용 수업안과 함께 배포 근거 문서, 오용 금지, 삭제·위기응답, 롤백과 스모크 테스트 완료

7 · 결과 화면 계획

기존 UI는 활용하고 학생용 의미는 분리한다

영역기존 clean-style에서 재사용학생용 변경
화면 구조 결과 전환, 차트 컨테이너, 다시 하기 같은 저수준 화면 패턴 대표 유형 중심 순서는 재사용하지 않고 탐색·성찰·실천 흐름으로 별도 구성
공통 UI 버튼, 탭, 반응형 여백, 임시 알림, 차트 컨테이너 학생 제품 색상·글자 크기·터치 영역과 쉬운 표현 적용
결과 내용 짧은 피드백을 전환해 보는 상호작용 이번에 본 관점, 다른 관점, 다시 생각하기, 다음 행동으로 표현
공유 공유 버튼과 화면을 밀지 않는 완료 알림 기본 공유는 활동 초대 링크만 제공하고 개인 결과·축 값·행동·이유는 URL에서 제외
등장 연출 결과 전환과 차트 그리기 방식 약 1~2초 안에 캐릭터, 결과명, 차트 순으로 표시하고 과도한 축하 효과는 제외

학생용 결과 계약

  • 공통 정체성: 모든 학생은 관점 탐색가이며 4개 관점은 등급이나 성격유형이 아닌 함께 생각해 보는 동료입니다.
  • 4개 관점 동료: 공정 레이더, 밸런스 메이커, 코어 키퍼, 브레이브 무버마다 전용 캐릭터·색상·한 줄 설명을 둡니다.
  • 6개 관점 지도: 공정 감지, 공감 시야, 원칙 판단, 결과 균형, 가치 수호, 용기 실행을 레이더 형태로 그리되 숫자·등급·다른 사람과의 비교를 표시하지 않습니다.
  • 통합 패턴: 행동과 이유를 따로 더하지 않고 장면별 행동×이유 조합으로 관점과 성찰 질문을 정합니다.
  • 연구 분리: 파일명·타입·문항 ID에 demo 또는 DEMO-를 사용하고 연구용 scoringVersion은 계속 unscored-p0로 유지합니다.
  • 결과 표현: “너의 스타일” 대신 “이번 세 장면에서 함께한 관점”이라고 표현하며, 응답이 적거나 조합이 상충해도 낮은 등급처럼 보이는 결과를 만들지 않습니다.

캐릭터는 유아용 마스코트나 직업 고정관념보다 중·고등학생이 부담 없이 받아들일 수 있는 성별 중립적 탐색가·조율가·수호자·실행가로 제작합니다. 다섯 캐릭터의 화풍, 비율, 시선과 배경 밀도는 통일하고 특정 동료만 화려하거나 우월하게 보이지 않게 합니다.

행동×이유 통합 규칙

각 장면의 16개 조합을 아래 교차 규칙으로 처리합니다. 행동이 안전하고 건설적인 대응일 때만 이유와 결합해 관점 지도와 동료 캐릭터를 강조합니다. 부분 대응·회피 행동은 이유만 좋더라도 긍정 결과로 합산하지 않고 해당 장면의 다른 관점 질문으로 연결합니다.

  • 응답 장면이 하나뿐이어도 대표 유형을 만들지 않으므로 최소 문항 수에 따른 등급 차이는 없습니다.
  • 레이더 내부값은 장면별 통합 패턴이 나타난 횟수 0~3만 사용하며 화면에는 숫자·눈금 설명·높고 낮음 표현을 표시하지 않습니다.
  • 스크린리더에는 값 대신 “이번 활동에서 함께 살펴본 관점” 목록과 다른 관점 질문을 제공합니다.
  • 4개 동료는 모두 결과 화면에 표시하고, 통합 패턴과 연결된 동료만 같은 크기 안에서 색으로 강조합니다.

공유·복원·접근성 계약

  • 기본 공유는 결과가 아니라 학생용 활동 시작 주소와 짧은 초대 문구입니다.
  • 개인 결과·축 내부값·questionId·choiceId·reasonId는 쿼리와 URL fragment 모두에 넣지 않습니다.
  • 결과 화면은 완료 응답을 검증하고 관점 지도를 계산한 뒤에만 원응답을 삭제하며, 새로고침 시에는 개인정보 없는 계산 결과를 현재 탭의 sessionStorage에서 복원합니다.
  • 공유·탭·다시 하기의 터치 영역은 최소 44px, 완료 알림은 role="status", 관점 지도에는 동일 내용을 담은 텍스트 요약을 제공합니다.
  • prefers-reduced-motion에서는 준비 대기와 캐릭터·차트 애니메이션을 모두 생략합니다.

실제 개발 순서

  1. 완료 · 배포 제어: 학생 자동 배포를 중지하고 수동 실행만 허용.
  2. 완료 · 구조 분리 기반: 제품 설정, 진단 등록부, 성인 청렴 호환 어댑터와 제품 구성 회귀 테스트.
  3. 구현 완료 · 학생 골격: 학생 전용 모듈·경로·검증 전 예시 문항·무채점 선택 돌아보기·저장 차단.
  4. 구현 완료 · 응답 계약: 배열 위치 대신 productId, instrumentId, questionId, choiceId, reasonId, 단계·완료 상태를 사용하는 버전형 계약.
  5. 진행 중 · 콘텐츠 작업: 코드와 분리된 후보 문항 검토판에 6개 영역 12개 2차 초안을 등록. 측정 목표·가치 갈등·수정 이력과 세 검토 상태를 각각 관리.
  6. 다음 · 데모 결과 계약: DEMO- 문항 ID, 행동×이유 통합 패턴, 6축 관점 지도, 활동 초대 공유 규칙을 별도 모듈과 테스트로 작성.
  7. 다음 · 결과 UI: 공통 UI 기반을 활용해 탐색가·관점 동료·관점 지도·다른 관점·다음 행동·공유·등장 연출을 학생용으로 구현.
  8. 공모전 전 확인: 모바일·키보드·움직임 감소·공유 링크·새로고침·잘못된 링크를 집중 점검하고 내부 사용자 검토를 기록.
  9. 공모전 이후 · 외부 검토: 필요 시 공통 검토 절차로 전문가 평정과 중·고등학생 인지면담을 진행하고 연구 후보를 확장.
  10. 검토 이후: 승인된 문항 버전과 검증 수준에 맞는 혼합·무분류 결과, 성장 미션을 연구 기능으로 별도 개발.
  11. 파일럿 이후: 승인된 경우에만 연구 저장·집계 기능을 별도 기능 플래그로 추가.
