1. 내부 설명 요약

일터 존중·안전 자가점검은 갑질, 직장 내 괴롭힘, 즉각적 안전위험을 공식 판정하는 도구가 아니다. 사용자가 자신의 상황을 구조화하고, 기록·상담·도움 연결을 빠르게 확인하도록 돕는 자가점검 및 안내 도구다.

  • 공식 기준을 참고하되, 공식 문항이나 자가검진 도구를 그대로 탑재하지 않는다.
  • 문항별 근거, 위험 플래그, 검토 상태는 내부 관리 파일과 문서에서 추적한다.
  • 이름, 소속, 연락처를 받지 않고 응답 배열을 서버나 URL에 남기지 않는다.
  • 자해·자살·폭력·즉각적 안전위험은 일반 점수보다 도움 연결을 우선한다.
  • 운영 공개 전에는 법·노무, 인권·고충처리, 정신건강·위기 문구 검토가 필요하다.
현재 구현은 파일럿·내부 검토용 초안이다. 운영 배포에서 공개하려면 NEXT_PUBLIC_ENABLE_RESPECT_PILOT=1 전환뿐 아니라 아래 승인 체크리스트를 완료해야 한다.

2. 범위와 한계

구분 한다 하지 않는다
법·노무 관계상 우위, 업무상 적정범위, 고통·근무환경 영향, 반복성 같은 판단 요소를 자가점검 문항으로 정리한다. 갑질 또는 직장 내 괴롭힘 해당 여부를 확정 판정하지 않는다.
조직 대응 기록 정리, 상담창구 확인, 보호조치 문의 같은 다음 행동을 안내한다. 기관의 공식 신고 접수, 조사, 징계 판단을 대체하지 않는다.
정신건강 도움 연결이 필요한 신호를 확인하고 109, 112, 119 등 긴급 경로를 먼저 보여준다. 정신질환 진단, 자살위험 점수 판정, 치료 권고를 하지 않는다.
AI 상담 향후 연결 시 판정 단정 금지, 기록·상담·도움 연결 중심의 응답 원칙을 둔다. AI가 상담기관, 고충처리 담당자, 의료 전문가를 대체하지 않는다.

3. 신뢰성 근거 체계

근거 흐름

  1. 공식 기준 문서 확인
  2. 기준을 판단 축으로 분해
  3. 직접 인용이 아닌 자체 문항 작성
  4. 문항별 출처·위험 플래그 기록
  5. 결과 문구와 행동 안내 연결
  6. 내부검토와 전문가 검토 후 운영 전환

현재 근거 문서

  • 공공분야 갑질 근절 가이드라인
  • 고용노동부 직장 내 괴롭힘 판단 및 예방·대응 매뉴얼
  • 국가정신건강정보포털 콘텐츠 이용안내
  • 109 자살예방상담전화, 112, 119 등 도움 연결 경로
신뢰성 통제 현재 반영 운영 전 보강
출처 추적 workplaceRespectQuestionGovernance.ts와 문서에 문항별 source, basis, risk flag를 유지 검토자, 검토일, review_status를 실제 검토 결과로 갱신
문항 공개 데이터 분리 화면용 문항 데이터와 내부 출처 메타데이터를 분리 운영 빌드에서 내부 메타데이터가 노출되지 않는지 정기 확인
단정 표현 방지 테스트에서 “갑질입니다”, “우울증입니다” 같은 금지 문구 점검 AI 상담 연결 시 시스템 프롬프트와 회귀 테스트 추가
위기 우선 시작·문항·결과 화면에 도움 연결을 두고 urgent 결과를 별도 처리 정신건강 전문가 또는 상담기관 기준으로 문구 확인
파일럿 가드 운영 기본값은 비공개, 파일럿 플래그가 있어야 공개 승인 전 플래그 전환 권한과 배포 절차를 명확히 지정

4. 결과 산출 설명

결과는 단순 합산 점수만으로 정하지 않는다. 현재 1차 구현은 다음 세 요소를 함께 본다.

  • 점수 각 문항 선택지의 위험 신호 강도를 0~3으로 반영한다.
  • 핵심 축 관계상 우위, 업무범위·방식, 존엄감 영향, 사적 요구, 불이익, 반복성 축이 함께 나타나는지 확인한다.
  • 위기 게이트 자해·자살·폭력·즉각 위험은 점수와 무관하게 도움 연결을 우선한다.
결과 의미 주요 안내
낮음 응답 기준으로 위험 신호가 뚜렷하지 않음 업무 목적 설명, 질문·거절 가능성 확보, 간단한 기록
주의 일부 축에서 부담이나 혼동 가능성이 있음 표현·방식 조정, 기록 정리, 상담창구 확인
높음 여러 핵심 축이 함께 나타나 보호조치나 공식 절차 검토 필요 중단, 분리, 기록 정리, 인사·감사·인권 담당자 상담
즉시 도움 필요 안전위험 또는 자해·폭력 신호가 있음 109, 112, 119, 가까운 사람 또는 책임자 연결을 우선
임계값은 1차 기준이다. 운영 전에는 내부 담당자 검토와 파일럿 응답 분포를 통해 과잉 안내와 누락 가능성을 확인해야 한다.

5. 데이터·개인정보 통제

항목 현재 설계 설명 가능 포인트
개인정보 입력 이름, 소속, 부서, 직위, 연락처를 묻지 않음 문항은 선택지형이며 자유입력은 1차 구현에서 제외
결과 전달 답변 배열을 URL에 싣지 않고 현재 브라우저의 sessionStorage에 임시 저장 공유 URL이나 서버 로그에 응답이 남지 않음
보관 시간 30분 TTL 후 결과 불러오기 차단 공용 기기에서 잔존 가능성을 줄임
사용자 삭제 결과 화면에 결과 지우기 제공 민감 응답을 사용자가 직접 지울 수 있음
운영 로그 문항별 응답 배열과 자유입력 원문 저장을 기본값으로 하지 않음 필요 시 오류 상태처럼 최소 정보만 남기는 원칙

6. 운영 전 승인 체크리스트

게이트 확인 질문 완료 증빙 상태
법·노무 갑질과 직장 내 괴롭힘 기준을 혼동하지 않고, 판정처럼 표현하지 않는가? 노무·감사·인권 담당 검토 의견 운영 전 필요
정신건강 자해·자살·폭력 위험 문구와 전화 연결 순서가 적절한가? 정신건강 전문가 또는 상담기관 기준 검토 운영 전 필요
개인정보 사용자 입력, URL, 로그, 세션 저장 방식이 개인정보 최소화 원칙에 맞는가? 개인정보 담당 또는 보안 담당 확인 운영 전 필요
문항 품질 문항이 일반 사용자에게 이해되고, 피해 가능자에게 과도한 부담을 주지 않는가? 파일럿 사용자 피드백, 문항 변경 이력 파일럿 중 확인
기술 검증 결과 계산, 위기 게이트, 세션 만료, 모바일 UI가 정상 동작하는가? 테스트 결과, 빌드 결과, 수동 QA 기록 일부 완료
운영 전환 파일럿 플래그 전환 권한, 롤백 방법, 담당자가 정해졌는가? 배포 체크리스트와 승인자 기록 운영 전 필요

7. 검증 계획

자동 검증

  • 문항 수, 선택지 수, 출처 메타데이터 필수 필드
  • 금지 단정 문구 미사용
  • 낮음·주의·높음·즉시 도움 필요 결과 산출
  • 위기 선택지의 urgent 라우팅
  • 잘못된 답변 인덱스 제외

수동 QA

  • 모바일 폭에서 문항·선택지 줄바꿈 확인
  • 긴급 도움 링크가 시작·문항·결과 화면에 보이는지 확인
  • 결과 지우기 후 재접속 시 결과가 사라지는지 확인
  • 파일럿 플래그가 꺼진 운영 빌드에서 공개되지 않는지 확인
  • 기관별 상담창구 안내가 추가될 경우 문구 충돌이 없는지 확인

8. 잔여 리스크와 대응

리스크 현재 대응 추가 대응
임계값이 실제 상황을 과소·과대 안내할 수 있음 핵심 축과 점수를 함께 사용하고, 확정 판정을 피함 파일럿 응답 분포와 담당자 피드백으로 조정
사용자가 결과를 공식 판정처럼 오해할 수 있음 자가점검, 기록, 상담, 도움 연결 중심 문구 사용 결과 화면에 “공식 판정 아님” 문구를 운영 전 추가 검토
위기 사용자가 문항을 끝까지 진행할 수 있음 시작·문항 화면에 긴급 도움 연결 표시 위기 도움 버튼의 시각적 우선순위와 문구를 전문가 검토
기관별 내부 절차와 앱 안내가 다를 수 있음 일반 상담창구, 인사·감사·인권 담당 등 범용 표현 사용 기관별 운영 시 상담창구와 보호조치 절차를 별도 설정
공식 자료나 전화 안내가 바뀔 수 있음 retrieved_at과 source_url을 내부 관리 분기별 또는 반기별 출처 재확인 일정 지정

9. 기관 설명 문안

짧은 설명

이 기능은 갑질 또는 직장 내 괴롭힘을 공식 판정하는 도구가 아니라, 사용자가 자신의 상황을 안전하게 정리하고 기록·상담·도움 연결을 확인하기 위한 자가점검 도구입니다. 문항은 공식 기준을 참고해 자체 작성했으며, 문항별 근거와 검토 상태를 내부적으로 관리합니다. 개인정보를 요구하지 않고, 응답은 서버나 URL에 저장하지 않는 것을 기본 원칙으로 합니다.

운영 승인 전 설명

현재 버전은 내부 검토와 파일럿을 위한 초안입니다. 공식 운영 전에는 법·노무, 인권·고충처리, 정신건강·위기 대응 문구 검토를 거쳐야 하며, 파일럿 응답과 사용자 이해도 확인을 통해 문항과 결과 기준을 조정해야 합니다. 운영 공개는 검토 상태가 내부검토 이상으로 올라가고, 파일럿 플래그 전환 승인자가 지정된 뒤에 진행합니다.
