일터 존중·안전 기획 배경

청렴 스타일 진단과 분리된 신규 흐름의 범위, 공식 자료 조합, 내부 근거 관리, 구현 순서

목차
1. 현재 결정 2. 사용자 입구 3. 공식 자료 조합 4. 내부 문항 출처 관리 5. 개인정보와 처리 원칙 6. 마음건강과 위기 연결 7. 구현 단계 8. 추가 검토 항목

1. 현재 결정

  • 기존 청렴 스타일 진단은 유지한다. 청탁, 이해충돌, 공정성, 규정 해석 등 윤리적 판단 성향과 조언을 다룬다.
  • 갑질·괴롭힘·마음위기 흐름은 별도 기능으로 설계한다. 기사 사례처럼 조직 내 권한관계와 심리 위험이 결합된 문제를 청렴 스타일 결과에 억지로 넣지 않는다.
  • 신규 기능의 작업명은 일터 존중·안전 자가점검으로 둔다.
  • 사용자 대상은 복잡하게 4개 이상으로 나누지 않고, 우선 내 행동 점검과 일터 존중 점검 두 입구로 시작한다.
  • 정신건강은 병명 진단이나 자살위험 판정이 아니라 자가점검, 위험 신호 확인, 도움 연결로만 다룬다.
  • 이 기능은 이름, 소속, 연락처 등 개인정보를 받지 않는 설계로 시작한다.
  • 공식 자료 사용과 문항 관리 기준은 자료 사용 및 문항 관리 기준 문서에 따른다.
  • 문항·결과·UI 1차안은 문항·결과 1차안 문서에 따른다.
  • 기관 내부 설명과 운영 승인 전 검토는 신뢰성 및 운영 승인 기준 문서에 따른다.
이 문서는 구현 전 계획 문서다. 공식 게시 페이지의 첨부 PDF 정보와 목차 수준까지 확인했지만, 문항 단위 반영 전에는 PDF를 내려받아 기준·사례·체크리스트를 내부 매핑표로 분해해야 한다.

2. 사용자 입구

내 행동 점검

예방형 내가 갑질을 하는 건가?

  • 내 말, 지시, 평가, 회식 요구, 사적 부탁이 괜찮은지 확인하고 싶은 사용자
  • 상급자뿐 아니라 프로젝트 리더, 선임자, 담당자, 민원 응대자처럼 관계상 우위가 생길 수 있는 사람도 포함
  • 결과는 “문제 없음”보다 “조정 필요”, “중단 필요”, “상담 필요”처럼 예방 행동 중심으로 제시

일터 존중 점검

보호형 내가 억울한데 이게 부당한가?

  • 상사의 말, 반복 지시, 업무 배제, 모욕, 불이익이 갑질이나 직장 내 괴롭힘에 가까운지 고민하는 사용자
  • 피해자라는 단어를 처음부터 쓰지 않고 “겪은 일” 중심으로 진입 장벽을 낮춤
  • 결과는 기록, 상담, 보호조치, 신고 전 준비, 마음건강 도움 연결 중심으로 제시
첫 화면의 큰 입구는 두 개로 유지한다. 다만 사용자가 “내가 예민한 건지, 상대가 문제인지 모르겠다”고 느끼는 경우를 위해 두 입구 아래에 잘 모르겠어요 보조 선택지를 두고, 현재 1차 구현에서는 행위자·당사자·목격자·지원자 관점을 구분하는 문장으로 직접 고르게 한다. 1~2문항 자동 안내는 선택사항으로 남긴다.

3. 공식 자료 조합

자료 확인된 근거 앱에서의 역할 반영 방식
공공분야 갑질 근절 가이드라인 국무조정실, 2019-02-22. 정책브리핑 첨부 PDF에 갑질 개념, 판단 기준, 주요 유형, 피해자 보호대책, 갑질 발생 위험진단 포함. 공공기관 맥락의 갑질 유형 분류와 위험도 진단 틀 법령 위반, 사적이익 요구, 부당한 인사, 비인격적 대우, 업무 불이익 등 유형을 참고하되, 체크리스트 직접 사용 여부는 이용조건 확인 후 결정
직장 내 괴롭힘 판단 및 예방·대응 매뉴얼 고용노동부, 2023-05-10 게시. 개정 제도·법령을 반영한 예방·대응 매뉴얼 PDF 첨부. 판단의 핵심 기준 지위·관계의 우위, 업무상 적정범위 초과, 신체적·정신적 고통 또는 근무환경 악화 여부를 판단 축으로 사용
국가정신건강정보포털 콘텐츠 이용안내 국립정신건강센터가 저작권을 보유. 일반 콘텐츠는 출처 명시와 공공누리 4유형 조건을 따라야 하며, 자가검진 도구는 자유이용에서 제외됨. 마음건강 자가점검 참고와 공식 도움 경로 연결 공식 자가검진 도구를 앱 안에 탑재하지 않고, 위험 신호 확인 문항은 별도 설계. 필요 시 공식 자가검진으로 링크아웃
위기 도움 경로 109 자살예방상담전화, 112, 119, 정신건강복지센터 등 긴급 위험 시 즉시 도움 연결 자해·자살·폭력·즉각적 안전위험 표현이 있으면 일반 AI 조언보다 도움 연결을 우선 표시
자료 조합은 “공식 문항 복사”나 “공식 도구 탑재”가 아니라 유형 분류 + 판단 기준 + 영향 확인 + 도움 연결의 4단 구조로 한다. 앱 문항은 공식 기준을 근거로 자체 설계하고, 내부 매핑표로 출처를 추적한다. 세부 사용 정책은 자료 사용 및 문항 관리 기준에서 고정한다.

4. 내부 문항 출처 관리

사용자에게 문항별 출처를 노출할 필요는 없다. 대신 내부적으로는 앱의 신뢰성과 설명 책임을 위해 모든 문항과 결과 문구가 어떤 기준에서 나왔는지 추적한다. 화면용 런타임 문항 데이터에는 내부 출처·검토 메타데이터를 싣지 않고, 별도 내부 관리 파일과 문서에서 추적한다.

question_id respect_action_001 문항 버전 추적
entry 내 행동 점검 / 일터 존중 점검 사용자 흐름 구분

source 공공분야 갑질 근절 가이드라인, 고용노동부 매뉴얼 근거 문서 추적

5. 개인정보와 처리 원칙

  • 이 기능은 이름, 소속기관, 부서, 직위, 연락처를 묻지 않는다.
  • 결과 저장을 계정·서버 기능으로 두지 않고, 사용자가 화면에서 바로 확인하는 일회성 자가점검을 기본값으로 한다.
  • 응답 배열은 URL 쿼리에 싣지 않고, 결과 화면 이동을 위해 현재 브라우저 탭의 sessionStorage에만 임시 보관한다. 1차 구현의 보관 시간은 30분이며, 결과 화면에서 사용자가 직접 지울 수 있어야 한다.
  • 자유입력이 들어가는 경우에는 이름, 기관명, 실명, 연락처를 쓰지 말라는 안내를 입력창 주변에 둔다.
  • AI 상담이 연결될 경우 사용자가 입력한 내용이 모델 처리에 사용될 수 있으므로, 민감한 식별정보를 넣지 말라는 안내를 별도로 둔다.
  • 운영 로그가 필요하면 오류 상태처럼 최소 정보만 남기고, 문항별 응답 배열과 자유입력 원문 저장은 기본적으로 하지 않는다.
“개인정보를 받지 않는다”는 원칙과 “사용자가 자유입력에 식별정보를 적을 수 있다”는 현실은 분리해 관리한다. 앱은 개인정보 입력을 요구하지 않고, 입력 안내와 로그 최소화로 우발 입력 위험을 낮춘다.

6. 마음건강과 위기 연결

  • 서비스 안에서는 “정신질환 진단”, “자살위험 점수 판정” 같은 표현을 쓰지 않는다.
  • 국가정신건강정보포털의 자가검진 도구는 자유이용 대상에서 제외되므로 공식 문항을 앱에 그대로 넣는 방식은 피한다.
  • 마음건강 관련 질문은 갑질 판단 점수가 아니라 도움 연결 우선순위를 정하는 안전 장치로 둔다.
  • 마음건강 질문은 기본적으로 일터 존중 점검의 후반부에서 선택적으로 묻고, 내 행동 점검에서는 사용자가 고통이나 위기 표현을 직접 입력한 경우에만 도움 연결을 우선한다.
  • 사용자가 자해, 자살, 폭력, 즉각적 위험을 표현하면 일반 결과 화면보다 긴급 도움 안내와 전화 연결을 먼저 보여준다. 시작 화면과 문항 화면에도 긴급 도움 연결을 노출해 위험한 사용자가 마지막 문항까지 기다리지 않게 한다.
  • 비긴급이지만 고통이 큰 경우에는 내부 고충상담, 정신건강복지센터, 공식 자가검진 링크를 안내한다.
AI가 “당신은 우울증입니다”, “자살위험 고위험군입니다”처럼 단정하지 않도록 프롬프트와 UI 문구에서 금지해야 한다.

7. 구현 단계

1차 구현은 내부 검토·파일럿 단계로 둔다. 운영 배포에서 공개하려면 NEXT_PUBLIC_ENABLE_RESPECT_PILOT=1을 명시하는 것만으로는 부족하며, 문항별 출처 위치 확정, 전문가 승인 기록, 개인정보·보안 검토, 기술 QA, 운영 전환 승인 절차가 필요하다. 세부 승인 기준은 신뢰성 및 운영 승인 기준에서 관리한다.
단계 작업 산출물 완료 기준
0 공식 PDF 원문 분해 자료 출처표, 목차 요약, 문항 후보 매핑 각 문항 후보가 최소 1개 공식 기준과 연결됨
1 자료 이용조건 확정 직접 사용, 요약, 기준 참고, 링크아웃, 허가 신청 여부. 세부 기준은 자료 사용 및 문항 관리 기준 문서에 기록 공식 도구·체크리스트를 앱에 직접 탑재하지 않는 원칙과 예외 승인 조건이 문서별로 결정됨
2 제품 흐름 확정 두 입구의 질문 흐름, 결과 등급, 도움 연결 기준. 세부 초안은 문항·결과 1차안 문서에 기록 내 행동 점검과 일터 존중 점검의 결과 문구가 분리됨
3 문항 데이터 모델 설계 문항 ID, 근거, 영역, 점수, 결과 연결 스키마 소스 매핑이 코드 또는 데이터 파일에서 추적 가능
4 메인 화면 정보구조 변경 청렴 스타일 진단 / 일터 존중·안전 자가점검 선택 화면 기존 청렴 진단 접근성이 떨어지지 않음
5 자가점검 UI와 결과 화면 구현 두 입구 문항, 결과 등급, 도움 안내 모바일에서 문항·결과·도움 안내가 겹치지 않고 읽힘
6 AI 상담 연결 역할별 프롬프트, 금지 문구, 위기 감지 라우팅 AI가 판정 단정 대신 기록·상담·도움 연결 중심으로 응답

8. 추가 검토 항목

  • 법·노무 갑질과 직장 내 괴롭힘 기준이 혼동되지 않도록 노무사 또는 관련 담당자 검토가 필요하다.
  • 정신건강 자해·자살 표현 처리 문구는 정신건강 전문가 또는 상담기관 기준 확인이 필요하다.
  • 저작권 공식 문항·체크리스트는 직접 탑재하지 않는 전제로 시작하되, 직접 사용하려면 문서별 이용조건과 허가 절차를 확인한다.
  • 개인정보 개인정보를 묻지 않고 결과 저장도 기본 기능으로 두지 않는다. 자유입력에는 식별정보를 쓰지 말라는 안내를 둔다.
  • 검증 구현 전에는 문항-근거 매핑 리뷰, 구현 후에는 문항 흐름 테스트와 위기 표현 라우팅 테스트를 추가한다.
