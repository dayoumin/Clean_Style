1. UI/UX 재사용 원칙

  • 기존 PublicLayout의 모바일 중심 카드형 폭, 여백, 배경을 그대로 사용한다.
  • 색상은 src/styles/globals.css의 디자인 토큰을 재사용한다. 새 팔레트를 만들지 않는다.
  • 문항 화면은 기존 ProgressBar와 QuestionCard 패턴을 따른다. 큰 문항 번호, 상단 영역 라벨, 세로 선택 버튼 구조를 유지한다.
  • 결과 화면은 기존 result-card, tip-box, 기본 CTA 버튼 스타일을 재사용한다.
  • 메인 화면은 기존 청렴 스타일 진단을 약화하지 않고, 두 개의 시작 선택지를 같은 밀도로 배치한다.
  • 정신건강·위기 안내는 경고색을 과도하게 쓰지 않고, “도움 연결” 행동이 먼저 보이게 한다. 시작 화면과 문항 화면에도 긴급 도움 연결을 노출해, 위험한 사용자가 마지막 문항까지 기다리지 않게 한다.
기존 요소 재사용 방식 신규 기능 적용
PublicLayout 모바일 우선 단일 컬럼, 데스크톱 중앙 프레임 /respect, /respect/check, /respect/result 후보 경로
ProgressBar 현재 문항/전체 문항 표시 각 입구 10문항 진행 표시
QuestionCard 상황 설명 + 4개 선택 버튼 문항 타입을 새 데이터 구조로 확장하거나 공통 QuestionCard 변형 컴포넌트 작성
choice-button 선택지 터치 영역과 hover/active 효과 빈도·강도 선택지에 그대로 적용
result-card 결과 요약, 조언 카드 위험 등급, 지금 할 일, 기록할 내용, 도움 연결 카드

2. 사용자 흐름

입구 A: 내 행동 점검

예방형 내가 한 말이나 지시가 괜찮은지 확인한다.

  1. 입구 선택
  2. 개인정보를 쓰지 말라는 짧은 안내
  3. 10문항 응답
  4. 결과 등급과 조정 행동 제시
  5. 필요 시 AI 상담으로 “어떻게 말하면 좋을지” 이어서 질문

입구 B: 일터 존중 점검

보호형 내가 겪은 일이 부당한지 확인하고 도움을 찾는다.

  1. 입구 선택 또는 “잘 모르겠어요” 보조 선택. 1차 구현은 직접 선택하되, 행위자·당사자·목격자·지원자 관점을 구분하는 문장으로 선택 부담을 줄인다. 자동 안내 문항은 다음 할 일로 둔다.
  2. 개인정보를 쓰지 말라는 짧은 안내
  3. 10문항 응답
  4. 결과 등급, 기록할 내용, 상담 경로 제시
  5. 위기 신호가 있으면 결과보다 도움 연결 우선

6. 결과 등급과 안내문

등급 내 행동 점검 일터 존중 점검 주요 행동
낮음 현재 응답만 보면 갑질 위험 신호는 낮음. 다만 표현과 절차는 기록. 현재 응답만 보면 직장 내 괴롭힘 판단 요소는 뚜렷하지 않음. 상황 기록, 기준 확인, 대화 방식 조정
주의 업무 필요성은 있어도 관계상 우위나 표현 방식에서 조정이 필요. 부당함을 느낄 만한 요소가 있어 기록과 상담을 권장. 표현 수정, 제3자 기준 확인, 기록 시작
높음 업무범위 초과, 모욕, 불이익 암시 등 위험 요소가 복합적으로 나타남. 직장 내 괴롭힘 판단 요소에 가까울 수 있어 내부 상담 또는 보호 요청 검토. 행동 중단, 상담창구 문의, 보호조치 검토
즉시 도움 필요 폭력, 보복, 심각한 압박, 위기 표현이 있으면 즉시 제3자 도움 필요. 자해·자살·폭력·즉각적 안전위험이 있으면 결과 요약보다 도움 연결과 전화 안내를 먼저 배치. 내 행동 점검은 접촉 중단, 거리두기, 112·119와 책임자 연결을 더 앞에 둔다. 109, 112, 119, 가까운 사람, 기관 상담창구 연결

7. 설문 텍스트 점검 기준

  • 기존 청렴 스타일 설문은 상황형 문장, 짧은 선택지, 비난하지 않는 말투를 재사용 참고점으로 삼는다.
  • 다만 일터 존중·안전은 성향 진단이 아니라 위험 신호 자가점검이므로, 기존처럼 성향을 가르는 선택지 대신 빈도·강도·안전 신호를 묻는다.
  • 문항은 “누가 잘못했는지”보다 “거절하기 어려웠는지”, “업무 범위를 넘었는지”, “고통이나 근무환경 영향이 있었는지”를 묻는다.
  • 사용자에게 이름, 기관명, 부서, 직위, 연락처를 쓰게 하는 문항은 만들지 않는다.
  • 결과 문구는 “갑질입니다”, “직장 내 괴롭힘입니다”, “우울증입니다”, “자살위험군입니다”처럼 확정하지 않는다.
  • 위기 문항은 점수 문항처럼 취급하지 않고 도움 연결을 우선하는 안전 게이트로 둔다.
점검 항목 기준 현재 1차안 판단
기존 청렴 설문과 톤간단한 한국어, 사용자를 탓하지 않는 문장대체로 충족. 직접 질문형의 부담은 시작 화면 안내와 “잘 모르겠어요” 보조 CTA로 완화함.
공식 기준 연결관계상 우위, 업무상 적정범위, 고통·근무환경 영향, 사적 요구, 불이익, 반복성문항별 source 메타데이터로 연결함.
단정 표현 금지법률·의료 판단을 확정하지 않음결과는 “가까울 수 있음”, “권장”, “검토” 중심으로 작성함.
민감정보 최소화개인식별정보를 묻지 않음문항은 개인식별정보를 요구하지 않음. 자유입력은 아직 없음.
위기 대응자해·자살·폭력 위험은 도움 연결 우선시작·문항 화면에 긴급 도움 연결을 노출하고, E10과 A10 urgent 결과는 전화 연결을 먼저 보여줌.

8. 진단 관련 추가 확인

  • 전문가 검토 법·노무, 인권, 정신건강 영역별로 문항과 결과 문구를 검토해야 한다.
  • 임계값 검증 낮음/주의/높음 기준은 현재 1차 기준이므로, 실제 응답 분포를 보며 조정해야 한다.
  • 사용자 이해도 “거절하기 어려운 위치”, “업무상 적정범위” 같은 표현이 일반 사용자에게 이해되는지 확인해야 한다.
  • 응답 부담 피해 가능자가 문항을 읽으며 다시 부담을 느끼지 않도록 문장 강도와 도움 안내 위치를 점검해야 한다.
  • 위기 문항 “가끔 스친다” 응답도 점수와 별개로 도움 연결을 항상 보여주는지 확인해야 한다.
  • 데이터 처리 응답 배열은 URL에 남기지 않고 현재 브라우저 탭의 sessionStorage에만 임시 저장한다. 보관 시간은 30분으로 제한하고 결과 화면에서 지울 수 있게 한다.
  • 결과 설명 결과 화면에는 관계상 우위, 업무범위, 불이익, 반복성처럼 확인된 주요 신호를 짧게 보여준다.

9. 구현 메모

  • 새 데이터 파일 후보: src/data/workplaceRespectQuestions.ts
  • 새 경로 후보: /respect, /respect/check, /respect/result
  • 결과 이동 시 응답 배열은 URL에 넣지 않고 sessionStorage로만 전달한다.
  • 화면에서 쓰는 문항 데이터와 내부 출처·검토 메타데이터는 별도 파일로 분리한다.
  • 문항 컴포넌트는 기존 QuestionCard를 바로 고치기보다, 공통 선택지 UI를 추출하거나 새 RespectQuestionCard를 만든다.
  • 기존 청렴 스타일 계산 로직과 섞지 않는다. 점수축과 결과 타입은 별도 파일로 분리한다.
  • AI 상담 프롬프트는 기존 청렴 스타일 프롬프트와 분리하고, 법률·의료 단정 금지 문구를 시스템 프롬프트에 둔다.
  • 테스트는 데이터 스키마, 점수 산출, 위기 게이트, 개인정보 안내 문구 노출을 우선한다.
