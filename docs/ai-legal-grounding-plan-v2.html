질문별 법령 조회·공유 캐시·명절 상담 계획

계획만 작성한다. 제품 코드·프롬프트·인증값·API 설정·서버·정기 작업·배포를 변경하지 않는다. 이전 초안과 두 에이전트의 비용·최신성 검토, 사용자의 명절/다른 법령 질문을 통합한 개정안이다. 실제 공식 API 연결과 상담 품질은 아직 검증 전이다.

법령 조회·캐시 보류 · 2026-10-14 사용자 결정. 공식 법령 조회·공유 캐시 구현은 후속 검토로 둔다. 청렴 상담 범위 판정과 재질문은 같은 날 후속 요청에 따라 별도 브랜치의 상담 범위 실험 계획으로 옮겨 검토한다. 현재 앱은 모델의 학습 지식과 저장된 시스템 프롬프트를 사용하며 실시간 법령 조회는 하지 않는다. 아래 법령 설계는 후보 계획이며 API 설정·정기 작업을 활성화한 것이 아니다. 이미 확인된 프롬프트 법률 오류는 TODO와 출시 QA의 미해결 항목으로 유지한다.

후속 검토: 청렴 상담의 범위

모든 법률 상담으로 확장하지 않고 청렴 스타일 해석 및 청렴과 관련된 행동·업무 상황을 중심으로 한다. 법령 이름이나 키워드만으로 허용 여부를 정하지 않는다. 다른 법령도 청렴 상황과 관련될 수 있으나 일반 법률 상담 전체를 제공한다고 안내하지 않는다.

입력검토할 대응
청렴 관련성이 명확함결과 해석, 선물·접대, 연구비·공금, 이해충돌, 공정한 업무 처리, 기록·신고 등 앱 주제 안에서 상담한다.
관련성이 애매함예: 상사와 사이가 나쁘다는 질문에는 부당한 업무 지시·공정성·규정 문제인지 짧게 확인한다. 일반 갈등을 억지로 청렴 문제로 해석하지 않는다.
명백히 무관함여행·투자 추천·일반 코딩 등에는 상담 범위를 짧게 안내하고 관련 질문 예시를 제시한다. 인사·감사에는 자연스럽게 짧게 답한다.

공개 서비스 참고: 국민비서 상담 도움말의 분야 선택·자동완성·자주하는 질문, 법제처 Lawbot의 법령 검색 목적 안내. 이는 공개 화면의 범위 안내 사례이며 내부 분류·거절 알고리즘을 검증한 것은 아니다. 향후 명확/애매/무관 질문 및 후속 대화의 맥락을 별도 검증한다. 현재 코드·프롬프트는 변경하지 않는다.

목표와 현재 증거

공식 자료 조회만으로 상담의 정확성이 자동 보장되는 것은 아니다. 올바른 법령·시행 시점·예외를 선택하고, 부족한 사실을 확인하고, 모델 답변을 조회 근거와 대조해야 한다. 현재 확인한 것은 두 스타일의 Luna 실제 응답 5개, 기존 자동 검사 10개, 혼합 질문 분류 오류와 입력 계약이다. 조회를 통합한 실제 응답 검증은 수행하지 않았다.

기본·Plus 성인 청렴 AI가 대상이다. 먼저 청탁금지법과 시행령, 이해충돌 방지법과 시행령으로 검증한다. 다른 법령은 공식 검색으로 확장하되 검색 성공과 상담 근거 확보를 구분한다. 학생 AI 활성화, 별도 일터 존중 프롬프트 개편, UI 재설계, 전 법령 일괄 수집, 자동 알림·배포는 범위 밖이다. 기존 20회 한도와 길이 기준 요약 정책은 보존한다.

질문에 따른 동작

질문계획한 처리
허용 여부·금액 한도·법적 의무·제재 등 상담관련 법령 근거를 자동 확인한다. 이전 상담의 후속 질문도 포함한다. 조회 여부가 애매하면 적용 사실을 확인하거나 조회 쪽으로 처리한다.
“법령을 찾아줘 / 근거를 보여줘”명시적 조회 요청은 스타일/중립 분류와 무관하게 조회 흐름으로 진입한다. 유효한 공식 자료 캐시는 사용할 수 있고 마지막 확인 시각을 표시한다.
“지금 최신 법령으로 다시 확인해줘”목록·원문 캐시를 모두 우회해 재조회한다. 실패하면 최신이라고 표시하지 않는다.
인사·감사·순수 스타일 설명법령 조회를 생략한다. 스타일 표현과 실제 업무 질문이 섞이면 상담을 우선한다.
기관 내부 규정법령 조회만으로 해당 기관의 내부 규정까지 확인했다고 가정하지 않는다. 확인된 별도 자료가 없으면 추가 확인이 필요하다고 구분한다.

처리 순서: 질문·맥락 → 근거 필요 여부 → 대상·사건 시점 확인 → 공식 현행/연혁 및 하위 법령 조회 → 관련 조문·부칙·별표 묶음 → Luna 설명 → 근거·시행일·확인 시각. 근거가 부족하면 법적 숫자·허용 여부를 모델 기억으로 메우지 않는다.

캐시는 사용자 간 공유하되 법령별로 분리

캐시 대상초기 후보분리 기준
버전 확인 정보15분 또는 다음 시행 경계 중 빠른 시각법령 식별값·현행/예정/연혁 구분·확인 시각. 법률 질문마다 유효 상태를 검사하고 만료 시 공식 목록 재조회.
본문·부칙·별표동일 버전 1시간, 새 버전은 즉시 갱신법령 식별값·버전·자료 종류·파서 버전. 같은 버전의 내용 정정도 주기적 원문 재조회로 확인.
선물·외부강의 등 주제별 근거구성 자료의 검증 상태에 종속관련 법령 버전·내용 해시·조문/별표 범위. 일부 근거가 바뀌면 연계된 묶음도 갱신.
질문별 적용 판단질문마다 사실관계 확인사건 기준일·대상 조건·맥락을 반영. 개인별 완성 답변은 다른 사용자에게 공유하지 않음.

15분/1시간은 공식 규칙이 아니라 제안값이다. 실제 호출량·지연·허용 가능한 재확인 간격을 측정해 확정한다. 원문 재확인을 6~24시간으로 늘리는 절감안은 같은 버전 정정 감지가 더 늦어진다는 조건과 함께 비교한다. 업데이트를 미리 안다고 가정하지 않는다. 원천 반영 지연과 조회 직후 변경까지 즉시 보장하는 것도 아니다.

설·추석 선물 질문

여러 사용자가 동일한 법률·시행령·별표·검증된 공식 명절 안내의 근거 묶음을 재사용할 수 있다. 그러나 개인별 허용 판단은 선물 종류, 상품권 여부, 주고받는 날짜, 가액, 직무관련성과 관계에 따라 다시 확인한다. 해당 연도·명절의 날짜 및 특례 기간은 공식 근거로 확인하며, 기간의 시작/종료를 넘으면 적용 선택을 갱신한다. 명절 한도 숫자만으로 모든 선물이 허용된다고 답하지 않는다.

첫 요청 때 공통 근거를 저장하고 후속 사용자들이 유효한 자료를 재사용하도록 한다. 자동 사전 조회·명절별 정기 알림은 이번 단계에서 만들지 않는다. 품목·날짜·가액 등이 빠져 결론이 달라지면 필요한 사실만 짧게 묻는다. 예외·정의·별표 주석을 입력 길이 절감을 이유로 임의로 잘라내지 않는다.

다른 법령을 묻는 경우

공식 법령명/본문 검색으로 관련 법률·시행령·시행규칙과 연결 근거를 찾는다. 먼저 검증하는 4개 법령의 근거를 다른 법령 질문에 억지로 적용하지 않는다. 관련성·시행 시점·필수 연계 규정이 확보되면 해당 근거 안에서 설명한다. 근거가 충분하지 않으면 추가 확인 질문 또는 찾은 공식 자료의 안내까지만 제공하고 법적 결론을 추측하지 않는다. 임의의 모든 법령에 대해 검증된 상담을 제공한다고 표현하지 않는다.

에이전트 검토에 따른 자료 계약

  • 버전 확인 성공, 원문 검증 성공, 마지막 시도, 실패 시각을 분리한다. 캐시 열람이나 실패로 성공 시각을 연장하지 않는다.
  • 본문·부칙·별표의 버전과 파싱 성공이 일치하는 완결된 묶음만 교체한다. 목록 성공/원문 실패를 전체 성공으로 처리하지 않는다.
  • 상태는 검증됨·정책상 유효한 캐시·만료·미확보·불완전으로 구분한다. 만료·미확보·불완전 자료로 현재 법적 금액·의무·허용 여부 결론을 생성하지 않도록 제한한다.
  • 가능한 경우 인용한 버전에 고정된 공식 링크를 사용한다. 링크를 모델이 생성하지 않고 서버의 근거 식별값과 연결한다.
  • 공식 자료를 사용자 간 공유하는 저장소 하나를 선택한다. 프로세스 메모리는 보조로 쓰며 지역별 캐시를 전역 공유 저장소와 동일하게 가정하지 않는다.
  • 동시 동일 조회는 가능한 범위에서 묶고 재시도 횟수·총 시간을 제한한다. 분산 잠금·작업 큐는 측정된 필요가 있을 때 검토한다.

비용과 기존 프로젝트 참고

법령 목록과 본문은 공식 안내상 무료지만 호출 제한은 따로 적용된다. 캐시는 공식 호출·서버 처리·지연을 줄인다. Luna에 넣는 관련 근거는 입력 토큰 비용을 늘릴 수 있으므로 필요한 근거만 선별한다. 별도 AI 분류/법령 요약 호출은 초기 기본값으로 추가하지 않는다. OpenAI 프롬프트 캐시는 조건과 실제 읽기/쓰기 비용을 측정하는 추가 후보이며 법령 API 캐시와 다르다.

scientific-name-validator의 lib/law-api-client.ts, scripts/legal-species-sync/check-law-version-changes.ts에서 공식 호출·오류 처리·인증값 마스킹·버전과 내용 비교를 참고한다. 그 프로젝트의 주간 동기화 주기를 대화의 최신 확인 주기로 복사하지 않는다. 폐기된 scripts/law-amendment-check는 사용하지 않는다. 인증값의 기존 사용 범위·승인과 Clean Style Worker의 실제 연결은 미확인이고 이번 단계에서 키를 조회·복사하지 않는다.
