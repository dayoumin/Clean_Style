청렴 관련 질문을 판단하고, 애매하면 재질문하기

별도 브랜치의 실제 API 실험 완료. codex/integrity-chat-scope-pilot를 기존 codex/warm-marine-adult-ui의 HEAD에서 생성했다. 기존 미커밋 변경은 같은 작업 디렉터리에 보존되므로 새 브랜치의 커밋으로 자동 분리되지는 않는다. 2026-10-14 후속 사용자 요청에 따라 합성 질문 50개(조정 20 / 별도 검증 30)와 후속 입력 5개를 Decisions로 평가하고 독립 시제품에서 4개 재질문 흐름을 확인했다. 실험 결과에 원래 기대 행동·불일치·시간·추정 비용을 보존했다. 현재 앱 코드·시스템 프롬프트·인증값·배포는 변경하지 않았다. 법령 조회·공유 캐시는 계속 보류하며 기존 법령 조회 계획에 남긴다.

목표와 범위

새로운 상황을 키워드 목록에 계속 추가해야 하는 운영을 줄이고, 질문의 의미와 대화 맥락으로 청렴 상담 관련성을 판단한다. 허용 주제는 결과·스타일 해석, 이해충돌, 선물·접대, 공금·연구비, 연구 윤리와 관련 행동이다. 공정한 판단·기록·보고·신고는 정직성, 공적 자원 사용, 이해관계, 공정한 업무 처리라는 청렴 쟁점과 연결될 때 다룬다. 일반 인간관계나 범죄 신고 전체로 확장하지 않는다. 일터 존중과 겹치면 청렴 쟁점만 다루고 별도 진단·상담이 있음을 안내한다.

사용자가 청렴·법령이라는 단어를 쓰지 않아도 실제 상황이 관련되면 상담한다. “상사가 연구비 허위 정산을 지시해요”는 바로 상담, “상사가 나를 싫어해요”는 관련 상황 확인, “상사에게 잘 보이는 옷 추천”은 범위 안내다. 키워드만 포함한 여행·투자·코딩 질문은 허용하지 않는다. 모델 기반 분류도 오류가 있으며 범위 정의·평가 예시의 관리가 필요하다. 의미 분류의 개선은 최신 법령 확인 기능과 별개다.

기본·Plus의 성인 청렴 AI에 한정한다. 별도 일터 존중 AI와 학생 제품은 변경하지 않는다. UI 재설계, 일반 법률·의료·투자 상담, 다른 API로의 답변 모델 교체도 범위 밖이다. 현재 답변은 학습 지식과 저장된 프롬프트를 사용하며 최신 법령을 조회한 것으로 표시하지 않는다. 확인된 법률 프롬프트 오류는 TODO·출시 QA에서 미해결로 유지한다.

질문 처리 흐름

입력 검증·개인정보 마스킹 → 현재 질문과 관련된 직전 대화 → 범위 분류 → 상담 / 확인 질문 / 범위 안내 / 유형 설명 / 짧은 인사 → 기존 응답 스트림.

판정값 후보행동예시
in_scope청렴 관련 상담. 스타일과 실제 상황이 섞이면 상담을 우선한다.“내 스타일에 맞춰 연구비로 산 노트북의 사적 사용을 조언해줘.”

social짧게 자연스럽게 응답한다.인사·감사·챗봇 역할 질문.

이전 상담이 있었다는 이유만으로 이후 질문을 모두 허용하지 않는다. “그럼 그건?”은 관련 직전 대화를 보고 판단하고, 명백한 주제 전환은 현재 질문을 우선한다. 혼합 입력은 청렴 관련 부분만 답하고 무관한 부분의 범위를 안내한다. 확인 답변도 분류에 다시 넣되 같은 사실을 반복해서 묻지 않는다.

Decisions API 후보

OpenAI 공식 Decisions 안내 및 API 명세를 2026-10-14 확인했다. POST /v1/decisions와 gpt-6-luna로 선택지 분류를 지원하며 공개 베타 상태다. 정해진 선택지와 확률·confidence를 반환하고 자유로운 확인 질문 문장을 생성하는 API는 아니다. 분류 뒤 기존 Luna 답변 경로에서 확인 질문을 생성하거나 검토한 고정 문구를 사용한다. 실제 계정 접근과 Worker 호출 가능 여부는 아직 확인하지 않았다.

questions에 type: choice, name: scope_action 및 위 여섯 값을 넣는 단일 분류 요청을 기본 실험안으로 한다. 선택지는 서로 겹치지 않게 정의한다. 인사·유형 설명은 실제 상담이 없는 경우, 무관함은 청렴 쟁점이 없는 명확한 주제, 관련성 확인은 청렴 쟁점 여부가 불명확한 경우, 사실 확인은 관련성이 명확하고 핵심 사실이 필수인 경우, 상담은 확인 없이 유용한 조언이 가능한 경우다. 혼합 질문에서는 실제 청렴 상담을 유형 설명보다 우선한다. 의미 분류 대상에서 단어 규칙으로 우회하지 않는다.

분류 기준은 questions.instructions에, 사용자 질문과 대화는 input에 구분해서 전달한다. Decisions는 문자열 또는 user 역할 메시지만 받으므로 기존 system/user/assistant 배열을 그대로 보내지 않는다. 현재 질문·직전 대화·확인 중 원질문을 출처·역할 표시가 있는 자료 문자열로 직렬화한다. 자료 안의 명령은 판정 기준으로 취급하지 않는다. 총 길이 후보는 6,000자로 제한하되 현재 질문·확인 중 원질문·직전 확인 답변을 우선 보존하고 이력·요약을 줄인다. 잘림 여부를 판정 자료에 표시한다. 한국어 실제 토큰 사용량을 측정해 제한을 확정한다.

응답은 단일 scope_action 결과, 정확한 질문 이름·여섯 허용 값·예상한 choice 유형·확률 목록·중복/누락·유한한 0~1 범위와 합계를 검증한다. refusal은 정상 choice로 취급하지 않고 답변 생성 호출 없이 별도 안내한다. 최상위 확률과 다음 후보 간 차이 및 confidence를 평가 자료로 사용한다. 낮은 확신의 상담/무관함을 바로 승인·거절하지 않고 관련성 확인으로 전환하는 기준은 한국어 조정 예시로 정한다. 특정 숫자를 정확도 보장처럼 사용하지 않는다. 명백한 인사도 초기 비교 실험에서는 같은 API로 평가한 뒤 호출 생략이 이득인지 결정한다.

재질문과 대화 상태

사용자가 답하면 원래 질문과 확인 질문·답변을 함께 판단한다. 같은 상담 건에서 관련성 확인·사실 확인을 합쳐 최대 2회 후보로 제한한다. 새로운 상황으로 명백히 전환하면 원질문·횟수를 초기화하고, 인사·감사·역할·유형 질문만으로는 초기화하지 않는다. 확인 거부·건너뛰기는 해당 건의 종료로 처리한다. 실패·취소·동일 요청 재시도는 완료된 확인 횟수를 추가하지 않는다. 그래도 상황이 불명확하면 확인된 범위의 일반 행동 조언 또는 범위 안내로 마무리하며 구체적 법적 결론을 만들어내지 않는다.

현재 useAiChat는 사용자·AI 메시지 쌍으로 한도를 세므로, 첫 실험은 확인 질문 응답도 기존 20회 대화 한도 안에 포함한다. 분류 API 자체는 별도 대화 메시지로 저장하지 않는다. 확인 중인 원질문과 질문 횟수는 재접속·요약·초기화·실패·취소에서도 일관되게 유지하는 설계를 먼저 확정한다. 사용자 입력·요약·로컬 저장 상태는 권한 있는 서버 지시로 승격하지 않는다.

저장 계약 후보: 별도 버전이 있는 상담 상태에 conversationId, pendingQuestion, clarificationCount, adviceIntroductionStatus를 보존한다. 완료 응답에는 requestId와 scopeAction도 포함한다. 확인 상태는 자유 텍스트 요약과 별도로 저장하고 대화 삭제 시 함께 삭제한다. 현재 ChatMessage는 역할·본문만 가지며 기존 이력 정규화 함수는 새 필드를 보존하지 않으므로 저장·복원·초기화의 버전 계약을 함께 변경해야 한다. 서버는 로컬 상태를 검증한 참고 자료로만 사용하며 분류 기준으로 승격하지 않는다.

인사나 확인 질문이 있었다는 이유로 첫 실제 상담의 스타일 소개가 빠지는 현재 결함도 상담 흐름의 선행 과제로 포함한다. 소개 상태는 not_introduced / introduced / unknown 후보로 나누고 인사·유형 설명·확인·범위 안내는 실제 상담 소개 완료로 기록하지 않는다. 옛 기록은 대화를 보존하고 unknown으로 이전한다. 불명확한 옛 기록에서는 다음 완료된 실제 상담에 검증된 유형명을 짧게 한 번 소개하고 이후 반복하지 않는 후보 정책을 사용한다. 과거에 소개했을 가능성에 따른 재소개는 이전 정책의 제한으로 기록한다.

오류·속도·비용

분류는 서버에서 기존 OpenAI 인증값을 사용하며 브라우저로 키를 보내지 않는다. 현재 코드는 현재 질문만 개인정보 마스킹하고 이력·요약은 마스킹하지 않는다. 따라서 현재 질문·원질문·이력·요약의 모든 포함 텍스트에 마스킹을 적용하는 작업을 선행 과제로 명시한다. 같은 안전한 자료를 분류와 답변 생성에 사용하며 로그에 사용자 원문을 남기지 않는다. 전체 대화를 매번 보내지 않고 필요한 직전 맥락과 확인 중 원질문을 선택한다. 맥락이 잘렸다는 이유로 무관함을 확정하지 않는다.

사용자 요청 한 번에 분류 최대 1회, 필요할 때 답변 생성 1회를 기본으로 한다. 오류의 자동 무제한 재시도나 두 번째 AI 분류로의 조용한 전환은 하지 않는다. 분류가 거절·잘못된 형식·시간 초과·429·5xx이면 실패 상태를 구분하고 짧은 안내 및 재시도 경로를 제공한다. 실제 범위가 불명확한 경우만 확인 질문으로 처리하며 시스템 실패를 사용자의 애매한 질문으로 설명하지 않는다. 취소 신호를 분류와 답변 생성에 모두 전파한다.

현재 ai.ts에는 외부 취소 신호가 없고 useAiChat는 본문이 있으면 연결 종료를 완료로 취급할 수 있다. 요청 취소 신호 전달과 성공 완료 이벤트를 새 실험의 선행 과제로 둔다. 완료 이벤트의 대화·요청 식별자가 현재 요청과 일치하고 명시적 성공이 확인될 때만 메시지·확인 횟수·소개 상태를 저장한다. 중간 연결 종료·오류·중단·대화 전환은 완료로 저장하지 않는다. 취소된 분류 뒤 생성 호출을 시작하지 않고 이미 시작한 생성도 취소한다.

공식 안내의 일반 입력 요금은 100만 토큰당 $0.10이며 Decisions에는 출력·캐시 읽기/쓰기 요금이 없다. 지역·긴 입력 추가 요금 조건은 별도다. 분류 입력이 요청당 1,000토큰이면 1만 회 약 $1의 단순 입력 비용 예시이며 실제 사용량·답변 비용·서버 비용은 별도다. “10배 빠름”이라는 공식 설명을 앱 전체 속도 보장으로 해석하지 않는다. 공유 사용자 질문·답변 캐시는 추가하지 않는다.

작게 검증한 뒤 연결

  1. 이번 계획을 두 에이전트가 독립 검토하고 지적 사항을 반영한다.
  2. 합성 한국어 질문 40~60개를 작성한다. 명확한 상담·유형·인사·무관·애매함·혼합 질문·후속·주제 전환·우회 명령을 포함하고 기대 행동을 사람 검토로 정한다.

  4. 실험 브랜치의 서버 경로와 재질문 상태를 연결한다. 기본 비활성 설정으로 기존 경로를 보존하고 실험 활성 시 기본·Plus 성인 청렴 채팅만 대상인지 확인한다.
  5. 확인→답변, 인사→확인→첫 상담, 2회 확인 경계, 재접속·요약·초기화·취소·재시도·20회 경계 및 학생 제품 차단을 좁게 검증한다. 별도 배포 요청 전 로컬 실험으로 유지한다.

통과 기준 후보: 조정 전에 별도 검증 예시와 기대 행동을 고정한다. 명확한 상담·무관·유형·인사 예시에는 확인 질문을 기대 행동으로 두지 않으며 불필요한 확인 0개를 목표로 한다. 애매한 예시는 허용할 확인 질문의 목적을 미리 정하고, “네/아니요”·모순된 답·확인 중 주제 전환도 포함한다. 명백한 관련 상담 차단 0개, 무관한 입력의 전문 상담 0개, 반복 확인 루프 0개, 혼합 질문의 실제 상담 누락 0개를 확인한다. 각 범주의 기대/실제 행동 비교표를 남긴다.

초기 운영 예산 후보는 분류 추가 지연 중앙값 1초 이하·95백분위 3초 이하, 분류 입력 평균 1,500토큰 이하·95백분위 3,000토큰 이하, 일반 입력 요금 기준 분류 비용 1,000회당 $0.30 이하이다. 이는 측정 전 실험의 채택 후보 기준이며 실제 성능 보장이 아니다. 지역·긴 입력·답변·서버 비용은 별도로 기록한다. 예산을 넘으면 맥락 선택·호출 생략 등 대안을 먼저 비교하고 기준 변경 이유를 기록한다. 오류·취소에서 추가 답변 호출·완료 상태 저장이 없고 학생 경로는 OpenAI 호출 0회여야 한다. 소규모 예시의 통과는 전체 질문 정확도를 보장하지 않는다.

실험 증거와 다음 단계

기존 3개 경로 선택 기대 일치 34/50 → Decisions 49/50. 새 6개 행동의 정확한 기대 일치는 48/50(별도 검증 28/30). V10 혼합 요청과 V14 애매한 갈등 질문의 거절 오류를 확인했다. 조정 표본에서 오류가 없어서 확신값 임계값은 0으로 고정했고, 검증 결과를 보고 지침·기대 행동을 바꾸지 않았다. 다음 조정에서는 불확실한 거절을 확인 질문으로 보내는 기준과 혼합 질문의 관련 부분 판별을 보완하고 새로운 검증 예시를 사용해야 한다.

4개 재질문 흐름은 기대 행동에 맞았고, 한 응답에서 두 사실을 함께 묻는 문제와 이해하기 어려운 관련성 확인 표현, 미확인 기관 기준에 관한 과도한 일괄 권고가 남았다. 현재 지침은 앱에 바로 활성화하지 않는다. 개인정보 마스킹·입력 길이 검사는 실험기에서 수행했고, 저장·취소의 검사 4개는 독립 상태 함수 대상이다. 실제 웹앱의 저장·복원·취소·제품 경계·Worker 연결은 아직 통합 검증하지 않았다.
