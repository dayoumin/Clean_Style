# 별도 HTML 파일 배포

기본 제품은 기존 Cloudflare 서버 배포입니다. `build:html`은 성인 기본형
`clean-style`의 파일 버전을 별도로 만들며 서버 빌드·배포·환경 파일·비밀값을 사용하지 않습니다.
Plus와 학생 제품은 이 생성 명령의 대상이 아닙니다.

## 소스 관리와 배포 요청

서버와 HTML은 장기 브랜치를 나누지 않고 `main` 한 곳에서 관리합니다. 최신 `main`에서
짧은 작업 브랜치를 만들고, 공통 화면·문항·이미지는 한 번 수정합니다. HTML 전용 이동·저장·PNG
기능만 `src/products/adult/standalone/`에서 다룹니다. 공통 화면 구조를 바꾸면 HTML 연결 코드도
검토하고 서버 빌드와 HTML 생성·집중 검사를 각각 확인한 뒤 `main`에 통합합니다.
통합·배포 확인 후 작업 브랜치를 정리하며, 다음 HTML 수정도 최신 `main`에서 시작합니다.

| 사용자 요청 | 실행 범위 |
| --- | --- |
| 배포 | 기본 서버용 빌드·배포 |
| HTML 배포 | 이미지와 코드를 포함한 단일 HTML 생성; 파일 전달은 사용자가 진행 |
| 둘 다 배포 | 서버 배포와 HTML 생성 |
| 수정 | 수정·검증만 진행; 배포는 별도 요청 때 실행 |

`build:html`만 실행하면 서버를 배포하지 않습니다. 2026-10-20 기본 서버 workflow를 수동 실행으로
전환했습니다. 이 설정이 원격 `main`에 반영된 뒤에는 커밋·푸시·병합만으로 서버를 배포하지 않습니다.
수정·커밋·푸시·병합 요청은 서버 배포 승인이 아니며, 서버 배포를 명시적으로 요청받았을 때만
`gh workflow run deploy.yml --ref main`을 실행하고 빌드·배포·AI 검사 완료를 확인합니다.
수동 이벤트와 main 브랜치가 모두 맞아야 배포됩니다. HTML 생성물을 서버 배포 workflow에 넣거나
자동으로 외부 전달하지 않습니다.

전달 대상은 **Windows PC**입니다. 실제 확인한 환경은 Windows Edge의 파일 실행이며,
휴대폰 배포·사진 앱 저장은 지원 범위에 포함하지 않습니다. 파일 전달은 사용자가 진행합니다.

| 항목 | 기존 서버용 | 별도 HTML용 |
| --- | --- | --- |
| 생성 명령 | `corepack pnpm build` | `corepack pnpm build:html` |
| 산출물 | 기존 Next/OpenNext 경로 | `artifacts/html/clean-style.html` |
| AI 조언·서버 기록 | 기존 기능 유지 | 없음 |
| 결과 보관 | 기존 정책 유지 | 이 브라우저의 이전 결과 및 PNG 저장 |
| 이미지·코드·스타일 | 서버 제공 | HTML 파일 내부에 포함 |

## 생성·전달

Windows PowerShell에서 프로젝트 루트 기준:

```powershell
$env:COREPACK_HOME = 'D:\Projects\Clean_style\artifacts\tool-cache\corepack'
corepack pnpm build:html
```

`artifacts/html/clean-style.html`을 더블클릭해 브라우저로 엽니다.
사용자에게는 **HTML 파일 하나만 전달**하면 됩니다. 함께 생성되는 `manifest.json`은
버전·생성 시각·SHA-256·포함 이미지 목록을 확인하는 제작자용 기록이며 실행에는 필요 없습니다.
생성물은 Git에서 제외된 `artifacts/`에 두고, 생성 명령을 서버 배포 workflow에 연결하지 않습니다.
기존 `build`, Next 설정, Worker 설정, GitHub Actions는 이 기능에서 바꾸지 않습니다.

## 서버 화면과의 일치

별도의 화면을 다시 작성하지 않습니다. 서버의 `home-page.tsx`, `test-page.tsx`,
`ResultClient.tsx`, public layout과 공통 컴포넌트·스타일을 HTML 생성 시 직접 묶습니다.
문항 아이콘·보기 높이·그림 전환·완료 이름 입력·결과 그래프/탭·이전 결과 창을 공유합니다.
2026-10-19 사용자 요청에 따라 HTML 결과 화면의 세 성향 배지는 생략합니다. 같은 성향은
레이더의 축 이름과 수치로 읽습니다. 서버 화면에는 이 변경을 적용하지 않습니다.
HTML 전용 연결 코드는 서버 파일을 수정하지 않고 생성 중 메모리에서만 적용합니다.
기대하는 원본 구조가 바뀌면 생성기가 실패하므로 변경 내용을 다시 검토해야 합니다.

의도한 차이는 AI 조언 대신 `이미지로 저장`, 파일 링크 공유 및 세 성향 배지 제외, API·서버 기록 전송 제외,
HTML 전용 저장소입니다. 이름은 이전 결과를 다시 열 때도 유지합니다.
2026-10-19 문항 설명의 2줄·3줄 차이로 선택지와 그림이 밀리지 않도록 서버와 HTML 공통 스타일에서
질문 영역에 현재 줄 높이의 3배(`min-block-size: 3lh`)를 확보합니다. 확대·좁은 화면에서
4줄 이상이 필요하면 내용이 잘리지 않게 늘어납니다. HTML 전용 높이 보정은 제거했습니다.
생성 기록 `manifest.json`에는 사용한 화면·스타일 파일의 SHA-256도 남깁니다.

2026-10-19 실제 배포 화면을 읽기만 하여 PC 1100×900의 홈·문항 3개·완료·결과·주의 탭·이전 결과
총 8개 상태와 대조했습니다. 측정한 주요 요소의 위치·크기·글자 크기·여백은 동일했습니다.
비교 프로필에서 서비스워커와 API·비 GET 요청을 차단했으며 배포하지 않았습니다.
증거: `artifacts/html-screen-parity-current/index.html`, `comparison.json`.
이 대조는 세 배지 생략 전 기록입니다. 배지 생략 후 결과 영역 검증은
`artifacts/result-sections-review/browser-review.json`과 같은 폴더의 PC 캡처를 참고합니다.
과거 `artifacts/html-screen-parity/` 보고서는 초기 개선 전 화면입니다.

이미지가 완성되거나 문항이 수정되면 명령을 다시 실행합니다. 생성 시점의 문항·채점·결과
원본과 최신 문항 이미지 목록을 읽으며 누락 이미지가 있으면 생성을 실패시킵니다.
사용 중인 홈·문항 30종·결과 8유형·대기·CSS 배경·favicon을 내장합니다.
외부 CDN·폰트·API 없이 실행하며 HTML의 보안 정책(CSP)도 네트워크 연결을 차단합니다.
글꼴은 기존 제품과 같이 시스템 글꼴을 사용하므로 기기에 따라 자형이 조금 다를 수 있습니다.

## 이전 결과·진행 복원

- 이전 결과는 최대 10건이며 기록이 없으면 메인 버튼을 숨깁니다.
- 같은 파일을 같은 브라우저로 다시 열면 저장 가능한 환경에서 기록과 진행을 복원합니다. 마지막 답변 후 결과 보기를 누르기 전에도 답변을 보존합니다.
- 완료 이름 입력 단계는 임시 결과 ID·이름을 보존하며 새로고침해도 기록을 중복 생성하지 않습니다.
- 결과 이동은 완료 화면의 방문 기록을 교체하고 임시 진행을 정리합니다. 뒤로·앞으로 이동해도 완료한 검사가 15/15 이어하기로 나타나지 않습니다. 과거 결과를 열어도 별도로 진행 중인 답변은 지우지 않습니다.
- 완료 이름 입력 도중 홈으로 나간 뒤 같은 기록을 이전 결과에서 열어도 최신 이름을 결과·PNG에 반영하고 그 완료 초안을 정리합니다. 다른 기록을 열 때는 진행 중인 답변·이름 초안을 유지합니다.
- 서버 사이트의 이전 결과와 자동으로 합치지 않습니다. HTML 전용 저장 키를 사용합니다.
- 응답에는 진단·채점 버전을 기록하고, 손상되었거나 버전이 다른 기록은 결과로 표시하지 않습니다.
- 파일 이동·이름 변경·다른 브라우저·시크릿 모드·브라우저 데이터 삭제 시 보존을 보장하지 않습니다.
- 브라우저가 저장을 거부해도 현재 검사는 마칠 수 있습니다. 결과 보관 실패를 안내하고 PNG 저장을 제공합니다.
- 기록 삭제에 실패하면 삭제됐다고 표시하지 않습니다.

## 결과 이미지

HTML 결과 화면의 `이미지로 저장`을 누르면 PNG를 브라우저 안에서 생성합니다.
별도 보고서 양식을 다시 그리지 않고 현재 결과 화면의 배치·색·이름·유형·설명·그림·실제 SVG 그래프와
**저장 시 선택한 탭의 내용**을 복사합니다. 조작 버튼·저장 안내만 제외하며 제거한 세 배지도 다시 넣지 않습니다.
따라서 강점·주의·팁은 필요한 탭을 선택해 각각 저장할 수 있습니다. 버전·날짜·별도 제목은 덧붙이지 않습니다.
화면에서 측정한 가로 폭과 각 내용의 위치·크기는 유지하되, 저장 이미지의 아래 끝은 해석 본문과 원래 카드의
하단 안쪽 여백까지로 정합니다. 제외한 버튼과 화면 고정 높이 때문에 생기는 큰 빈 공간은 저장하지 않습니다.
2026-10-19 사용자 요청으로 저장 PNG의 본문 아래에는 `국립수산과학원`과 `청렴한 당신을 응원합니다.`를 넣습니다.
응원 문구를 위에, 작은 기관명을 아래에 배치하고 굵은 청록색 강조·민트 밑줄과 옅은 민트 배경으로 표현합니다.
이는 저장 이미지에만 추가하는 의도된 차이이며 현재 화면의 버튼·서버 결과·해석 내용은 유지합니다.
문구는 같은 시스템 글꼴을 사용하고 새 이미지·외부 폰트 요청은 없습니다. 응원 문구는 한 줄을 유지하고 기관명은 아래에 9px 간격으로 배치합니다.
이미지 변환 전 하단 문구에도 상속된 글꼴 크기를 명시적으로 고정하며, 실제 높이를 측정해 잘리지 않게 담습니다.
좁은 창의 투명한 본문 영역도 실제 성인 화면의 배경색을 채워 저장하므로 이미지 뷰어에서 검게 보이지 않습니다.

그림과 시스템 글꼴이 준비되고 초기 그래프 전환이 끝난 뒤 HTML 전용 렌더러로 2배 해상도의 PNG를 만듭니다.
복사 중에는 해당 결과의 탭 조작을 잠시 막아 본문과 그래프의 상태가 섞이지 않게 합니다. 화면에서 측정한 위치와
계산된 스타일을 복사하므로 저장용 배치의 별도 상수나 채점 계산을 유지하지 않습니다.
[html-to-image 공식 구현](https://github.com/bubkoo/html-to-image)을 HTML 안에 묶고 외부 CDN·서버 이미지 API·외부 폰트는 사용하지 않습니다.

한 번 누르면 바로 다운로드하며 별도 미리보기 창을 자동으로 열지 않습니다.
다운로드가 시작되지 않으면 같은 화면의 `다시 다운로드` 링크를 사용합니다.
새 파일명은 `clean-style-screen-<저장 시각 UTC>.png`이며 이전 보고서형 PNG와 구분됩니다.
재다운로드 링크도 처음 생성한 파일명과 이미지를 그대로 사용합니다. 이미 내려받은 과거 PNG는 변경되지 않습니다.
실패해도 결과와 기록은 유지됩니다. 이전 결과에서도 같은 방식으로 저장할 수 있습니다.

## 검증

```powershell
corepack pnpm exec vitest run src/__tests__/standalone-html.test.ts src/__tests__/standalone-html-navigation.test.ts src/__tests__/standalone-html-build.test.ts
node tests/standalone-html.verify.mjs
node tests/standalone-html-export.verify.mjs
```

두 번째 명령은 설치된 Windows Edge와 프로젝트에 버전을 고정한 Playwright 개발 의존성으로 **실제 파일 URL**을
네트워크 차단 상태에서 검사합니다. 서버를 시작하지 않습니다.
필요하면 프로젝트 지침대로 `TEMP`, `TMP`를 `artifacts/tool-cache/test-temp`로 지정합니다.
별도 브라우저 프로필만 사용하고 종료하며 사용자 브라우저나 다른 세션의 서버를 조작하지 않습니다.
증거는 `artifacts/html-verification/`에 저장합니다.

세 번째 명령은 사용자 파일 탭이나 그 저장소를 읽지 않는 별도 가상 결과 화면에서 원본 결과 컴포넌트·공통 스타일과
HTML 전용 저장 코드를 검사합니다. HTTP 요청은 검사 안에서 메모리로 응답하며 서버를 시작하지 않습니다.
첨부 화면과 같은 유형·표시 점수를 갖는 합성 답안을 고정해 같은 화면 크기·같은 탭의 실제 브라우저 캡처와 PNG를
전체 이미지 단위로 대조합니다. 하단 조작부와 불필요한 여백만 제외한 기준 화면이 원래 결과의 좌표를 바꾸지 않는지도
검사합니다. PC 3크기·7조건과 좁은 창 1조건에서 문구 한 줄·기관명 간격, 반복 저장의 픽셀 동일성, 저장 후 배치 유지, 외부 요청·실행 오류를 확인합니다.
증거와 비교 화면은 `artifacts/html-export-fidelity/`에 저장합니다. 이 컴포넌트 검사는 최종 파일의 실제 `file:` 실행
검사를 대신하지 않습니다. 도구 정책으로 파일 탭 접근이 막히면 그 미확인 상태를 릴리스 QA 문서에 남깁니다.

지원 범위와 확인 상태는 `docs/adult-design-release-qa.html`의 `standalone-html-device-export`
항목에서 관리합니다. 휴대폰은 사용자 지정 배포 범위에서 제외되어 별도 확인하지 않습니다.
